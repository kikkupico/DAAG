Proof · that R + W > N forces every read quorum to meet every write quorum

Let there be N replicas, a write quorum QW of size W and a read quorum QR of size R, both subsets of the same N replicas. Claim. If R + W > N, the two quorums share a replica.

  1. This is the standard property of strict quorums, which the paper recalls in §2. Let there be N replicas, a write quorum QW of size W and a read quorum QR of size R, both subsets of the same N replicas.
  2. |QW ∪ QR| ≤ N, since both are subsets of a set of size N.
  3. |QW ∩ QR| = |QW| + |QR| − |QW ∪ QR| ≥ W + R − N.
  4. If R + W > N, the right side is at least 1, so the two quorums share a replica. That replica holds the committed write, and a read that returns the value with the greatest version among its responses returns that write or a later one.∎

Yet with three home libraries, many choose W = 1 and R = 1 on purpose: waiting for only the fastest answer and the fastest reply makes writing and reading as quick as the nearest, least busy library. On the coast, waiting for one and asking one (W = 1, R = 1) is called the quick way.Yet in practice, practitioners with three replicas very often configure W = 1 and R = 1 on purpose! Why? Proof · that the probability of a read missing the last write is C(N − W, R) / C(N, R)

Let N be the number of replicas, W the write quorum size and R the read quorum size, the W replicas written and the R replicas read each chosen uniformly at random; C(n, r) is the number of subsets of size r of a set of size n. Claim. The probability ps that the read quorum misses the write quorum is C(N − W, R) / C(N, R).

  1. This is Equation 1 of §2.1, with the paper's assumption that the W replicas written and the R replicas read are each chosen uniformly at random.
  2. The read quorum is one of the C(N, R) subsets of size R, each equally likely.
  3. The read misses the write quorum exactly when every one of its R members lies among the N − W replicas not written to. There are C(N − W, R) such subsets.
  4. So ps = C(N − W, R) / C(N, R). For N = 3, R = W = 1 this is 2/3; for N = 100, R = W = 30 it is about 1.88 × 10−6, as the paper states.∎

That works well when an entry has 100 home libraries, where W = R = 30 misses fewer than twice in a million reads. But real stores keep three copies of an item, not 100, and still find the quick way well behaved. Two kinds of leeway explain it: leeway in versions (k) and leeway in time (t).That combinatorial miracle is great if an item has 100 replicas—where W = R = 30 misses less than twice in a million reads. Real systems, however, keep N = 3 copies of each item, not 100! Why, then, do operators find W = 1, R = 1 so well-behaved when N = 3? Because two things come to the rescue: leeway in versions (k), and leeway in time (t).

Proof · that under WARS no read is stale when R + W > N

WARS names the four delays: W, from the coordinator to a replica for a write; A, the acknowledgment back; R, a read request to a replica; S, the response back. Let the write be sent at time 0, reach replica i at wi and be acknowledged at wi + ai; it commits at wt, the Wth smallest acknowledgment time. Claim. If R + W > N, a read begun at any t ≥ 0 after commit is not stale.

  1. This is the remark of §4.1. Let the write be sent at time 0, reach replica i at wi (a draw from W) and be acknowledged at wi + ai (a draw from A). The write commits at wt, the Wth smallest of these acknowledgment times.
  2. The W replicas whose acknowledgments came first each received the write at wi ≤ wt.
  3. A read begins t ≥ 0 after commit, so its request to replica i arrives at wt + t + ri (a draw from R), which is at least wi for each of those W replicas. Such a replica returns the write.
  4. The read takes the first R responses, which are R distinct replicas. If R + W > N they cannot all lie among the N − W other replicas, so at least one is among the W that hold the write, and the read is not stale.∎

The method of §5.1 for the general case: draw N samples from each of W, A, R and S; compute wt, the Wth smallest of the sums W[i] + A[i]; order the replicas by R[i] + S[i]; and count the read stale when each of the first R satisfies wt + R[i] + t ≤ W[i]. Repeating this many times gives the probability for each t.

To verify that this four-leg replay matches reality, the authors tested it against an instrumented Apache Cassandra cluster across 50,000 writes. The predicted t-visibility curve matched the measured staleness to within 0.85% on average.

The paper behind this book

Peter Bailis, Shivaram Venkataraman, Michael J. Franklin, Joseph M. Hellerstein and Ion Stoica, Probabilistically Bounded Staleness for Practical Partial Quorums. Proceedings of the VLDB Endowment, Vol. 5, No. 8 (38th International Conference on Very Large Data Bases, Istanbul, August 2012), 776–787. — Partial quorums, PBS k-staleness, t-visibility and monotonic reads, the WARS model, and a Monte Carlo evaluation on production latency data.

The ideas, plainly.

Bailis and co-authors study data kept on several machines, where a write is acknowledged after W of N machines have it and a read returns after R machines have answered. If R + W exceeds N, a read always meets the latest write. Operators often choose smaller numbers, for speed, so that a read may miss it. The paper asks how often, and shows that a read within k versions of the latest has probability 1 minus p to the k, where p is the chance of a plain miss: the chance of being stale falls exponentially with the leeway allowed. Monotonic reads is the same idea with k set by how often a reader returns compared with how often the data is written.Bailis and co-authors study data kept on several machines, where a write is acknowledged after W of N machines have it and a read returns after R machines have answered. If R + W exceeds N, a read always meets the latest write. Operators often choose smaller numbers, for speed, so that a read may miss it. The paper asks how often, and shows that a read within k versions of the latest has probability 1 minus p to the k, where p is the chance of a plain miss: the chance of being stale falls exponentially with the leeway allowed. Monotonic reads is the same idea with k set by how often a client returns compared with how often the data is written.

Staleness in time is harder, because writes keep reaching more machines after they are acknowledged. The paper models the four message delays of a write and a read, W, A, R and S, shows that a read is stale when its request reaches a replica before the write does, and works out the odds by simulation using measured delays. The results are that the delay of the write message, and above all its variance, matters most, and that typically the chance of reading the latest write is high within a short time of its commit, at a latency far below that of a strict quorum.

What the paper offers is therefore a probability and a way to tune it, not a guarantee: the worst case stays unbounded, and the odds rest on assumptions about independence and about the delays staying as they were measured.
