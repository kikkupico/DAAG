Knowing When to Wait

Which problems can a distributed system solve consistently without machines ever waiting to coordinate with one another—and which problems provably force them to wait?

We find out at the hall of two doors at the fork of Paxos, where every question is sorted by its logical shape toward either the scholars' coast or the assemblies.

We find out by sorting programs by their logical shape: those that only ever add to their output can run on a group of machines without waiting for one another, and those that rest on an absence cannot.

Only growing, stated exactly

A program P is monotonic if for any input sets S and T with S ⊆ T, P(S) ⊆ P(T). In a question, anything answered on fewer facts is still answered on more. The papers call a question confluent when it gives the same answers whatever the order and grouping of the news.

Questions that rest on absence

A question rests on an absence (`non-monotonic`) whenever a new fact can take away an answer that looked true before. Is this every copy? really asks Is there no copy other than these? What would make the answer safe

Knowing that nothing more is coming

Before a library can safely output an answer that rests on an absence, it must be certain that no missing fact is still on the road. That means hearing from the other libraries and agreeing that the input is complete—which is the exact work of an assembly, and the exact thing that stalls when couriers are stopped.Before a machine can safely output an answer that rests on an absence, it must be certain that no missing fact is still in transit. That means hearing from the other machines and agreeing that the input is complete — which is exactly what coordination is, and exactly what stalls during a partition.

      The CALM theorem, as the papers state it

      A program has a consistent, coordination-free distributed implementation if and only if it is monotonic. Equivalently, for any query Q: Q is computed by a coordination-free transducer network, if and only if it is computed by an oblivious one, if and only if Q is monotone.

      Proof, in outline · that coordination-free, oblivious and monotone are equivalent

      A network N of nodes runs a transducer Π at each node. The input I is spread over the nodes by a horizontal partition H. Π is oblivious if it uses neither the relation Id (its own identifier) nor All (the identifiers of all nodes). Π is coordination-free if on every network, for every I, some partition has a run that reaches quiescence by heartbeat transitions only, that is, without reading a message. Claim. A query Q is computed by a coordination-free transducer iff by an oblivious one iff Q is monotone.

      1. This is Corollary 13 of Ameloot, Neven and Van den Bussche, with the definitions of their paper. A network N of nodes runs a transducer Π at each node: each node holds a part of the input I (a horizontal partition H of I over N), and repeatedly ingests received facts, updates local relations by queries, sends facts to other nodes and outputs. A run reaches quiescence when no more messages change anything. The network N with Π is consistent if every fair run on every partition of I outputs the same set, and Q(I) is that set. Π is oblivious if it uses neither the system relation Id (its own identifier) nor All (the identifiers of all nodes). Π is coordination-free on N if for every instance I there exist a horizontal partition H of I and a run on H that reaches a quiescence point by heartbeat transitions only, and coordination-free if it is so on every network.
      2. Monotone ⇒ oblivious (Theorem 6, outline). Given a monotone query Q, let each node send all the facts it holds to all other nodes, and at every step output Q of everything received so far. By monotonicity every output is a subset of Q(I), so no output is retracted, and in every fair run every node eventually holds all of I and outputs Q(I). This transducer uses neither Id nor All. (The paper's construction handles the query languages of its model with more care.)
      3. Oblivious ⇒ coordination-free (Proposition 11). On a one-node network, given I, an oblivious Π reaches quiescence with the output Q(I) by heartbeat transitions alone. On any other network place all of I at every node. Since Π is oblivious, a node cannot tell that it is not alone unless it communicates, so by heartbeats it acts as on the one-node network and each node outputs Q(I).
      4. Coordination-free ⇒ monotone (Theorem 12). Let Q be computed by a coordination-free Π, let I ⊆ J and t ∈ Q(I). Take a network with at least two nodes. By coordination-freeness there is a partition H of I on which t is output at some node v by heartbeats only. Let v′ ≠ v and define the partition H′ of J by H′(v) = H(v) and H′(v′) = H(v′) ∪ (J ∖ I). The partial run on H up to the output of t is also a partial run on H′, and extends to a fair run, so t is output on J. By consistency t ∈ Q(J). Hence Q(I) ⊆ Q(J).
      5. The three steps give (3) ⇒ (2) ⇒ (1) ⇒ (3).∎
      Proof · that the emptiness query is not coordination-free

      The query asks, of an input set S spread over the nodes, whether S is empty. Id gives a node its own identifier and All the identifiers of all nodes; a heartbeat transition is a step in which a node reads no message. Claim. No transducer computes the query coordination-free, and the query is not monotone.

      1. This is Example 10 of the same paper. The query asks, of an input set S spread over the nodes, whether S is empty. Every node can hold a part of S.
      2. A transducer that computes it makes each node send out its identifier, read from Id, on condition that its local S is empty, forwards identifiers received, and outputs ‘true’ when it has received the identifiers of all nodes, checked against All.
      3. On any partition, to output ‘true’ a node must know that every other node's part is empty, which it can only learn from a message. So no partition, including the one that gives every node the whole input, lets the output be reached by heartbeats alone. Hence the query is not coordination-free, and it is not monotone: S = ∅ gives ‘true’ and a larger S does not.∎

Knowing that monotonic problems need no coordination still leaves the designer two hard tasks: figuring out whether a problem can be reformulated monotonically (as CRDTs do for counters and sets), and implementing it efficiently.

      Was the original 2010 conjecture true word for word?

      Not quite. Hellerstein originally phrased CALM in terms of syntactic `Datalog` rules without negation, and Ameloot et al. showed that some semantically monotonic queries over ordered domains cannot be expressed in positive Datalog. What was proved—and what matters—is semantic monotonicity (S ⊆ T ⇒ Q(S) ⊆ Q(T)).

      Setting The Hall of Two Doors

      The paper behind this book

      Joseph M. Hellerstein, The Declarative Imperative: Experiences and Conjectures in Distributed Logic. SIGMOD Record 39(1), 2010, 5–19; the text of the keynote at the ACM Symposium on Principles of Database Systems (PODS), 2010. — The CALM conjecture and its companions.

      Tom J. Ameloot, Frank Neven and Jan Van den Bussche, Relational Transducers for Declarative Networking. arXiv:1012.2858, December 2010; Journal of the ACM 60(2), 2013. — The formal definitions of consistency and coordination-freeness and the proof of the CALM theorem.

      Joseph M. Hellerstein and Peter Alvaro, Keeping CALM: When Distributed Consistency Is Easy. arXiv:1901.01930, January 2019; Communications of the ACM, 2020. — The theorem restated, with examples, design patterns and open questions.

      The ideas, plainly.

      Hellerstein asked which computations a group of machines can carry out without ever waiting for one another, so that they stay available when the network is cut and are not slowed by coordination. His conjecture, CALM, is that those are exactly the monotone computations: ones whose output only grows as the input grows, so that no answer ever has to be retracted. Deadlock detection is monotone, since a cycle found stays found. Garbage collection is not, since to be sure an object is unreachable a machine must know that it has heard everything.

      Ameloot, Neven and Van den Bussche proved it in a model of machines running relational queries and exchanging facts. A computation is coordination-free if there is some distribution of the data on which it reaches its answer without messages; they show this is exactly the monotone queries, and also exactly those answered by machines that know neither their own names nor the others'. Without that knowledge a machine cannot tell that it has heard from everyone, which is what a non-monotone query needs.

      Hellerstein and Alvaro restate it for practice. A non-monotone step can often be isolated and sealed, so that only it waits, and only for what it names; coordination can be moved off the critical path; or an error can be apologised for afterwards. The result is a bright line, not a recipe: it does not say how to find a monotone form of a problem, and what it guarantees is that the outcome does not depend on the order of the news, not that it is the newest.

      Hellersteinos stands for Joseph Hellerstein, the author of the first and third papers. The papers have five authors, Joseph M. Hellerstein, Peter Alvaro, Tom J. Ameloot, Frank Neven and Jan Van den Bussche, and all are credited here; only Hellersteinos is named, and the librarians and scholars are told apart by what they do.
